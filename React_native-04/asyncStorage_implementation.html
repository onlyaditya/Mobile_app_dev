Activity · The four answers

Four homes for data

Owner = the copy that wins when two copies disagree.

1Local only

Only on the phone. The server never sees it.

2Remote only

Only on the server. Fetched every time, never kept.

3Remote + local cache

Server owns it. The phone keeps a throw-away copy.

4Local + remote backup

Phone owns it. The server keeps a sealed copy.

LossPhone lost. Is the data gone?

Requirement 1 · Survive a restart

useState lives in memory. Memory dies with the app.

App process · RAM

Device · Disk survives

RAM belongs to the running app.Swipe the app away, or let the OS close it, and the memory is handed back. Empty.

Disk belongs to the device.It is still there after a restart, even after the phone reboots.

Requirement 1 · Survive a restart

Keep a copy on disk

RAM

save ↓↑ load

Disk survives

Save when it changes. Load when the app starts.

Requirement 2 · The disk only understands text

Convert on the way in, and on the way out

{ id: 7, sender: "me", text: "Hi!" }
JSON.stringify
'{"id":7,"sender":"me","text":"Hi!"}'
save
Disk
{ id: 7, sender: "me", text: "Hi!" }
JSON.parse
'{"id":7,"sender":"me","text":"Hi!"}'
load

Text survives. Dates become strings, functions disappear.

Limits

  
What local storage is not

  

    
Not secure
Plain text
Anyone with the device's files can read it. Secrets go in the secure store.

    
Not permanent
A cache
Uninstall or "Clear data" wipes it. Always handle "nothing saved".

    
Not shared
One device
Your other phone sees nothing. Sharing needs a server.

Debugging · predict the symptom

  
Four bugs everyone hits

  

    
Forgot await
const saved = AsyncStorage.getItem(key);
saved is a Promise, not the text
await it, or use .then()

    
Forgot stringify
AsyncStorage.setItem(key, messages);
disk holds "[object Object]"
JSON.stringify(messages)

    
Forgot parse
setMessages(saved);
messages.map is not a function
JSON.parse(saved)

    
Saved in state only
setMessages(next);  // and nothing else
works until the next restart
write to state and disk

  







  
Requirement 5, again · when the list grows

  
10,000 messages? Use a database.

  

    

      
Key-value: one big string

      
const all = JSON.parse(await getItem("messages"));
all.filter((m) => m.text.includes("lab"));

      
reads and parses everything

      

      

    

    

      
Database: ask for what you need

      
SELECT * FROM messages
WHERE chat_id = 1 AND text LIKE '%lab%';

      
reads only the matches
