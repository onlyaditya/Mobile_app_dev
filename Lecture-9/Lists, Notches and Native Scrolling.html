Stop 4 · The React habit

Same .map(), different world

<View style={styles.list}>
  {chats.map((chat) => (
    <ChatRow key={chat.id} chat={chat} />
  ))}
</View>
Web
Content taller than the window? The browser adds a scrollbar for free.
Native
A View is just a box. Overflow is clipped. Nothing scrolls unless you ask for it.
Won't scroll

1 · View never scrolls

Rows 10 onwards exist in the tree, but they sit below the screen. The user can't reach them.

2 · Everything renders at once

500 chats means 500 native views created before the first frame. Slow start, high memory.

So we need a component that scrolls, and ideally one that renders less.

Stop 9 · The fix

Let the device tell you where it's safe

Rotated: insets are now left 59 · right 59 · bottom 21. Same code.
// npx expo install react-native-safe-area-context
import {
  SafeAreaProvider,
  SafeAreaView,
} from 'react-native-safe-area-context';

export default function App() {
  return (
    <SafeAreaProvider>
      <SafeAreaView style={{ flex: 1 }}>
        <Text style={styles.title}>Chats</Text>
        <FlatList data={chats} renderItem={renderChat} />
      </SafeAreaView>
    </SafeAreaProvider>
  );
}
Need the numbers? const insets = useSafeAreaInsets() gives top, bottom, left, right for custom padding. Use edges={['top']} to pad only some sides.
Why not React Native's own SafeAreaView? It only works on iOS and is deprecated in recent versions. The library works on iOS and Android.
Recap · What to reach for

Four rules for today's chat app

Avoid

.map() inside a View

No scrolling on native. Overflow is simply cut off.

Short content

ScrollView

Scrolls, but mounts every child up front. Fine for forms and settings.

Long lists

FlatList

Mounts a window around the screen. Needs data, renderItem, keyExtractor.

Every screen

Safe area

SafeAreaProvider once at the root, SafeAreaView on each screen.
